# Развертывание кластера Kubernetes

## Намерение
Создать кластер Kubernetes с четким разделением ролей узлов: мастер-нода для управления кластером, инфра-ноды для размещения инфраструктурных сервисов (Ingress, мониторинг, логирование, ArgoCD), воркер-ноды для размещения пользовательских приложений.

## Требования
1. Кластер должен состоять из:
   - **1 мастер-нода** — только для управления кластером (не должно быть пользовательских и инфра-подов).
   - **2 инфра-ноды** — для размещения инфраструктурных продуктов (Ingress-контроллер, система мониторинга, логирования, ArgoCD и т.д.).
   - **3 воркер-ноды** — для размещения пользовательских приложений.
2. Все узлы должны быть частью одного кластера Kubernetes.
3. На мастер-ноде не должно быть пользовательских и инфра-подов (taints и tolerations должны быть настроены соответствующим образом).

## Ограничения
1. Используется Managed Kubernetes от Cloud.ru.
2. Конфигурация узлов (количество vCPU, RAM) должна быть достаточной для планируемой нагрузки.
3. Настройка taints/tolerations должна быть выполнена на этапе создания кластера или после.

## Контекст
- В Cloud.ru можно создать кластер с несколькими группами узлов (node groups) с разными характеристиками.
- Для разделения нагрузок используются `nodeSelector` и `taints/tolerations`.
- Инфра-ноды должны иметь taint, чтобы обычные приложения на них не планировались, а инфра-сервисы — имели toleration.

## Тесты
1. Проверить количество узлов в кластере (`kubectl get nodes`).
2. Проверить, что на мастер-ноде нет подов, кроме системных (`kubectl get pods -A -o wide | grep <master-node>`).
3. Проверить, что инфра-поды (Ingress, ArgoCD, мониторинг) запущены на инфра-нодах.
4. Проверить, что пользовательские приложения запущены на воркер-нодах.

## Критерии приемки
- [ ] Кластер развернут с 6 узлами (1 мастер + 2 инфра + 3 воркер).
- [ ] Мастер-нода не содержит пользовательских и инфра-подов.
- [ ] Инфра-продукты развернуты на инфра-нодах.
- [ ] Приложения развернуты на воркер-нодах.
