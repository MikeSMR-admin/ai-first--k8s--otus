# Общие рекомендации

## Приоритеты
Начать с регистрации домена и создания кластера Kubernetes, затем развернуть инфраструктурные сервисы, после — приложение и GitOps.

### Порядок этапов:
1. **Регистрация домена** — получить бесплатный общедоступный домен (DNSHE, Kevin Service Registry).
2. **Создание кластера Kubernetes** — настроить 6 узлов (1 мастер + 2 инфра + 3 воркер).
3. **Развертывание инфраструктурных сервисов** — ArgoCD, мониторинг, логирование, Ingress.
4. **Развертывание приложения** — веб-приложение с СУБД и Kafka.
5. **Настройка GitOps** — автоматизация через ArgoCD.

## Документация
Все шаги должны быть задокументированы в коде (комментарии, README).

### Требования к документации:
- Каждый компонент должен иметь описание в соответствующем SPEC.md файле.
- Конфигурационные файлы должны содержать комментарии, объясняющие назначение параметров.
- README.md должен содержать общую информацию о проекте и инструкции по запуску.

## Безопасность
Не хранить секреты в коде, использовать GitHub Secrets и Kubernetes Secrets.

### Рекомендации:
- Использовать GitHub Secrets для хранения API-ключей, kubeconfig и других чувствительных данных.
- Применять Sealed Secrets или HashiCorp Vault для хранения Kubernetes-секретов.
- Не коммитить файлы с реальными секретами в репозиторий.
- Использовать `.gitignore` для исключения файлов с секретами.

## Тестирование
После каждого этапа выполнять проверки из разделов «Тесты» и «Критерии приемки».

### Типы тестов:
- **Функциональные тесты** — проверка работоспособности компонентов.
- **Интеграционные тесты** — проверка взаимодействия между компонентами.
- **Тесты доступности** — проверка доступности сервисов по доменному имени.
- **Тесты производительности** — проверка количества реплик, времени отклика.
