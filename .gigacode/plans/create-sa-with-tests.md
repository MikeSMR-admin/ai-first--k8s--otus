# План создания сервисного аккаунта в cloud.ru с автотестами

## Текущее состояние
- ✅ Уже есть инфраструктура для работы с SA:
  - Скрипты: `/auth--cloud-ru--for-api/`
  - Автотесты: `/tests/service-account/`
  - Конфигурация: `/auth--cloud-ru--for-api/config--env.sh`
  - Токен: `/opsx/cloud-ru-token.txt`

## Цель
Создать новый сервисный аккаунт в cloud.ru и запустить автотесты для подтверждения результата.

## План действий

### Шаг 1: Проверка текущей конфигурации
- Проверить файл `/auth--cloud-ru--for-api/config--env.sh`
- Убедиться, что KEY_ID, SECRET, PROJECT_ID заданы корректно
- Проверить, что токен валиден

### Шаг 2: Создание сервисного аккаунта
- Запустить скрипт создания SA: `./auth--cloud-ru--for-api/create-sa--script.sh`
- Или использовать существующий токен для прямого вызова API

### Шаг 3: Назначение роли сервисному аккаунту
- Выполнить API-запрос для назначения роли "platform.project.admin"
- Использовать ID созданного SA и PROJECT_ID

### Шаг 4: Запуск автотестов
- Запустить тест 1: Создание SA (`01-create-sa-test.sh`)
- Запустить тест 2: Получение информации о SA (`02-get-sa-test.sh`)
- Запустить тест 3: Проверка роли (`03-check-role-test.sh`)
- Или запустить все тесты через `run-tests.ps1` или `run-all-tests.sh`

### Шаг 5: Проверка результатов
- Проверить, что все тесты прошли успешно
- Убедиться, что SA создан, активен и имеет нужную роль
- Сохранить результаты тестов

## Ожидаемый результат
- Сервисный аккаунт создан в cloud.ru
- SA активен и имеет роль "platform.project.admin"
- Все автотесты пройдены успешно
- Результаты сохранены в `/tests/service-account/results/`

## Дополнительные замечания
- Использовать WSL для выполнения bash-скриптов
- Все команды должны выполняться из корня проекта
- При ошибках проверять документацию в `/docs/cloud-ru/`
